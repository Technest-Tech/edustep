# EduStep Academy OS

نظام موحّد لإدارة الأكاديمية: العملاء والمتابعات، المعلمون، الطلاب، الجروبات،
الحضور، المستويات، التحصيل المالي، والتقارير التشغيلية.

## المكوّنات

- `apps/api`: ‏Laravel 13 API مع Sanctum.
- `apps/web`: ‏Next.js 16 وReact 19 بواجهة عربية RTL.
- `infra`: تشغيل Docker وNginx.
- `docs/execution-blueprint`: الخطة الشاملة، المعمارية، نموذج البيانات، الصلاحيات، والـroadmap.
- `packages/api-contract`: مكان عقد OpenAPI والأنواع المشتركة.

## ما يعمل في النسخة الحالية

- تسجيل دخول آمن بجلسات Laravel Sanctum وحماية حسب دور المستخدم.
- مركز أمان للحساب يشمل تغيير كلمة المرور، التحقق بخطوتين، رموز الاسترداد،
  ومراجعة وإغلاق الجلسات المفتوحة.
- إلزام حسابات المدير والحسابات المالية بالتحقق بخطوتين في الإنتاج، وإجبار
  الموظف على تغيير كلمة المرور المؤقتة قبل الوصول لبيانات الأكاديمية.
- لوحة تشغيل لحظية للمؤشرات، المتابعات، مسار التحويل، والجروبات.
- CRM للعملاء: بحث وتصنيف، سجل تواصل، متابعة، اختبار مستوى، ورحلة قبول مترابطة.
- مركز قبول موحّد للعروض، الحصص التجريبية، حجوزات المقاعد، وقوائم الانتظار.
- عروض تسجيل بحالة وصلاحية وخصم واعتماد، مع تحويل العرض المقبول إلى طالب وفاتورة مرة واحدة.
- مركز إدارة للأكاديمية يجمع الهوية وبيانات التواصل وأيام العمل وقواعد التشغيل الافتراضية.
- إدارة حسابات الفريق من الإنشاء والتعديل والإيقاف إلى إعادة تعيين كلمة المرور وإغلاق الجلسات المفتوحة.
- سبعة أدوار واضحة بصلاحيات منفصلة، مع حماية آخر حساب مدير نشط والحسابات المرتبطة بملفات المعلمين والأسر.
- سجل تدقيق تلقائي لكل عملية تغيير ناجحة مع المنفذ ورقم الطلب والحقول المتأثرة، دون تخزين قيم كلمات المرور.
- تطبيق إعدادات الأكاديمية تلقائيًا على صلاحية عروض التسجيل، مدة حجز المقاعد، وأرقام الطلاب والفواتير.
- حجز مقعد مؤقت يحتسب ضمن إشغال الجروب، والتحويل التلقائي لقائمة الانتظار عند اكتمال السعة.
- متابعة التجربة من الجدولة والتأكيد وحتى الحضور أو عدم الحضور، وربطها بمرحلة العميل.
- ملفات الطلاب والتسجيلات وبيانات ولي الأمر والجروب والرسوم.
- إدارة الجروبات والسعة الفعلية والمقاعد المحجوزة وقوائم الانتظار والمواعيد ونظام الدراسة وإنشاء جروب جديد.
- لوحة تشغيل تفصيلية لكل جروب تشمل الحصص القادمة والمكتملة ومؤشرات السعة والحضور.
- جدولة الحصص، تسجيل حضور جماعي، إنهاء الحصة، ومراجعة سجل الحضور.
- تقويم أسبوعي موحد لكل حصص الأكاديمية مع فلاتر المعلم والجروب والحالة.
- منع تلقائي لتعارض حصص المعلم أو استخدام القاعة في نفس الوقت.
- تقييمات أكاديمية قابلة للمتابعة مع الدرجة والتقدير وملاحظات المعلم.
- ملف طالب 360° يجمع التسجيل الحالي، انتظام الحضور، وسجل التقدم والتقييمات.
- ملف معلم 360° يجمع الجدول، الجروبات، اكتمال تقارير الحصص، والمستحقات.
- مساحة عمل خاصة بالمعلم تعرض حصص اليوم والجروبات والتقارير الناقصة وجدول الأسبوع.
- صفحة مستقلة لمستحقات المعلم تعرض المبلغ وحالة المراجعة والاعتماد والدفع.
- بوابة أسرة تربط ولي الأمر بأكثر من ابن وتعرض الحصة القادمة والحضور والتقدم والفواتير.
- مركز تواصل موحد بقوالب ورسائل مرتبطة بولي الأمر والطالب وسجل حالة لكل رسالة.
- رسائل داخلية تُسلّم داخل بوابة الأسرة، وقائمة انتظار صادقة للقنوات الخارجية حتى ربط مزوّد رسمي.
- تنقل وصفحة رئيسية وصلاحيات وصول مختلفة تلقائيًا للإدارة والمعلم وولي الأمر.
- عزل بيانات المعلم على جروباته وطلابه فقط، وبيانات ولي الأمر على الأبناء المرتبطين بحسابه فقط.
- إدارة باقات الدراسة حسب البرنامج والمستوى وعدد الحصص والمدة والسعر وخطة التقسيط الافتراضية.
- دورة اشتراك كاملة للطالب تربط التسجيل بالباقة، وتُنشئ الأقساط والفواتير المتوازنة تلقائيًا.
- متابعة حالة الاشتراك والتحصيل، مع التجميد وإعادة التفعيل والتجديد ومنع التجديد أو الاشتراك المكرر.
- توليد حصص الجروب من جدوله الأسبوعي خلال فترة محددة، مع تجاوز الإجازات والمواعيد المكررة والتعارضات.
- سجل مركزي لإجازات وإغلاقات الأكاديمية يُطبّق تلقائيًا أثناء توليد الجداول.
- مركز نجاح أكاديمي يعرض الحضور ومتوسط التقييم والمخاطر والتقارير لكل طالب.
- كشف تلقائي لمخاطر انخفاض الحضور أو متوسط التقييم، مع درجة خطورة ومسؤول متابعة.
- خطط تدخل أكاديمية بمواعيد وحالات ونتيجة تنفيذ مرتبطة بالطالب والتنبيه.
- تقارير تقدم دورية تبدأ كمسودة ثم تُنشر للأسرة بعد اعتماد الإدارة الأكاديمية.
- إشعار داخلي تلقائي لولي الأمر عند نشر تقرير تقدم جديد.
- صندوق طلبات خدمة لولي الأمر يغطي الأكاديمي والمواعيد والحسابات والدعم والشكاوى.
- استلام طلبات الأسرة وإسنادها وتسجيل الحل، مع متابعة الحالة من بوابة ولي الأمر.
- تضمين المخاطر الأكاديمية وطلبات الأسرة المفتوحة داخل مركز التنبيهات التشغيلي.
- احتساب مستحق المعلم تلقائيًا مرة واحدة من كل حصة مكتملة وفق قاعدة سعر مؤرخة.
- البرامج والمستويات ومسار التدرج الأكاديمي.
- فواتير ومدفوعات وأرصدة متأخرة وتسجيل التحصيل مع تحديث الرصيد تلقائيًا.
- دورة مصروفات من التسجيل إلى اعتماد المدير ثم الدفع، مع سجل مالي محفوظ.
- مراجعة مستحقات المعلمين واعتمادها وتسجيل دفعها من شاشة تشغيل مالية واحدة.
- مركز تنبيهات ذكي للمتابعات والتحصيل المتأخر والحصص القادمة.
- تقارير إدارية موحدة للحضور والتحويل والتحصيل وصحة الجروبات وأحمال المعلمين.
- واجهة عربية RTL متجاوبة ومهيأة للكمبيوتر والموبايل.
- تشغيل إنتاجي مستقل لخادم الويب والـAPI والـqueue والـscheduler مع PostgreSQL
  وRedis داخليين، وفحص جاهزية يشمل نبض المهام وآخر نسخة احتياطية موثقة.
- نسخ احتياطي يومي لقاعدة البيانات مع checksum وفحص صلاحية الأرشيف وسياسة
  احتفاظ، وأمر آمن لإنشاء أول مدير دون تحميل بيانات العرض.

## التشغيل المحلي السريع

المتطلبات: PHP 8.4، Composer، Node.js 24، وpnpm.

```bash
cd apps/api
cp .env.example .env
composer install
php artisan key:generate
php artisan migrate --seed
php artisan serve --port=8080
```

وفي نافذة أخرى:

```bash
cd apps/web
pnpm install
pnpm dev
```

- الواجهة: `http://localhost:3000`
- API health: `http://localhost:8080/api/v1/health`
- حساب الإدارة: `admin@edustep.local`
- حساب المعلم: `sara@edustep.local`
- حساب ولي الأمر: `parent@edustep.local`
- كلمة المرور المحلية الافتراضية للجميع: القيمة الموجودة في `SEED_ADMIN_PASSWORD`
  (الافتراضي في بيئة التطوير `Admin@12345`).

## التشغيل بالحاويات

بعد تجهيز `apps/api/.env` ومفتاح التطبيق:

```bash
docker compose up --build
```

ثم افتح `http://localhost:8080`. يقوم Nginx بتقديم الواجهة والـAPI من نفس
النطاق، وPostgreSQL وRedis يعملان كخدمات داخلية.

## تشغيل الإنتاج

ملف الإنتاج منفصل ولا يدخل Git. خطوات الإطلاق، النسخ الاحتياطي، الاستعادة،
والمراقبة موثقة في
[`docs/PRODUCTION-RUNBOOK.md`](docs/PRODUCTION-RUNBOOK.md).

```bash
cp infra/production.env.example infra/production.env
docker compose --env-file infra/production.env -f compose.production.yaml config --quiet
docker compose --env-file infra/production.env -f compose.production.yaml up -d --build
```

لا تستخدم `db:seed` في الإنتاج. أنشئ أول مدير بالأمر التفاعلي الآمن الموضح
في دليل التشغيل، ثم فعّل التحقق بخطوتين فور أول تسجيل دخول.
